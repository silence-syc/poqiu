## 一、赛题理解

### 1.1 比赛形式

CRTC2026 的核心形式是**机器人之间的资源争夺**：参赛队伍自行设计、制作 1-2 台机器人，在限定空间与时间内尽可能多地收集和占有道具资源（能量单元 / 能量核心），最终持有道具得分较多的一方获胜。

### 1.2 关键约束的提取

通读参赛手册后，我们提炼出四条直接决定设计方向的硬约束：

| 约束类别   | 具体要求                                              | 对设计的直接影响            |
| ------ | ------------------------------------------------- | ------------------- |
| **尺寸** | 初始尺寸 ≤ 290×195×210mm（手册 V1.6）；任意变形不得超出直径 550mm 球体 | 结构必须紧凑，机械臂的展开范围也要受控 |
| **重量** | ≤ 2.0kg                                           | 材料选型与结构强度必须平衡       |
| **供电** | 仅 1 个供电模块，额定电压 ≤ 7.4V，指定 18650 电池                 | 动力与电控的功耗必须严格核算      |
| **成本** | 新生组整机成本建议 ≤ 400 元                                 | 选型时必须在性能与成本间做取舍     |

### 1.3 从规则到功能的映射

我们把手册中的"考核指标"反向拆解为机器人必须具备的能力，形成总体设计的功能清单：

| 考核指标         | 对应的机器人能力       | 负责小组      |
| ------------ | -------------- | --------- |
| 外形展示         | 完整机体 + 能量单元安装位 | 机械组       |
| 电机运动（≥4）     | 四轮独立驱动         | 机械组 + 电控组 |
| 舵机运动（≥3）     | 机械臂多关节控制       | 机械组 + 电控组 |
| 底盘运动（PS2 手柄） | 全向底盘 + 遥控      | 电控组       |
| 尺寸规范         | 结构紧凑化设计        | 机械组       |
| 方块携带         | 夹爪收集机构         | 机械组       |
| 结构稳定性        | 180mm 掉落无零件脱落  | 机械组       |

> **为什么先做这张映射表**：手册的考核指标是按"结果"描述的（能完成几个电机、几个舵机），而工程实现是按"模块"组织的。**把"考核项"翻译成"功能模块"，是把评分标准落地的第一步**——它让每个小组都清楚自己要交付什么，也让文档的"功能板块"划分有了依据。

## 二、总体方案与系统架构

### 2.1 总体设计思路

基于"资源争夺 + 场地对抗"的特点，我们确定的总体方案是：

- **底盘**：四轮麦克纳姆轮全向底盘，PS2 手柄遥控，保证机动性与操控精度；
- **执行机构**：以**夹爪**为核心收集装置，将地面静止方块由"非携带状态"转为"携带状态"；
- **主控与电控**：STM32F103C8T6 为核心，DRV8833 驱动电机，独立降压模块为舵机供电；
- **视觉（探索中）**：ESP32-CAM 低成本方案，尝试辅助识别白色方块。

### 2.2 系统分层架构

```
┌─────────────────────────────────────────────┐
│              感知层（视觉组）                 │
│        ESP32-CAM → 白色方块识别               │
├─────────────────────────────────────────────┤
│              控制层（电控组）                 │
│  STM32F103C8T6                               │
│   ├─ PS2 手柄 SPI 通信（摇杆模拟量）          │
│   ├─ 麦轮运动学解算（4 电机 PWM）             │
│   └─ 舵机 PWM 输出（夹爪动作）                │
├─────────────────────────────────────────────┤
│              驱动层（电控组）                 │
│  DRV8833 ×4（电机） + 舵机直驱                │
├─────────────────────────────────────────────┤
│              能源层（电控组）                 │
│  18650 ×2 串联（7.4V）→ DC-DC 降压 5V        │
├─────────────────────────────────────────────┤
│              执行层（机械组）                 │
│  麦轮底盘 + 机械臂 + 夹爪                     │
└─────────────────────────────────────────────┘
```

> **为什么这样分层**：分层是为了**明确接口边界**。例如机械组只需要知道"夹爪由几个舵机驱动、安装尺寸多少"，电控组只需要知道"输出几路 PWM、电流多大"，两组可以并行开发、最后对接。**在只有几周备赛时间的情况下，清晰的接口划分是并行推进的前提。**

### 2.3 分组与协作机制

| 小组        | 核心职责                   | 关键交付物             |
| --------- | ---------------------- | ----------------- |
| **机械组**   | 底盘结构、机械臂与夹爪、3D 建模、结构强度 | 可装配的底盘与收集机构、3D 模型 |
| **电控组**   | 主控程序、电机/舵机驱动、供电、遥控     | 可运动的底盘、手柄遥控、稳定供电、机械臂控制  |
| **视觉组**   | 摄像头链路、图像识别、视觉供电        | 可运行的识别程序          |
| **文档与管理** | 进度记录、规范核对、材料提交         | 本文档、仓库、考核材料       |

从 9 月 19 日起，团队确立了"**有进展就记录**"的协作规范，并明确中期考核需要在 GitHub 仓库提交学习记录。这一规范是本文档能够完整还原开发过程的基础。

## 四、规范自检

| 规范项   | 要求                    | 我们的做法                                             | 状态  |
| ----- | --------------------- | ------------------------------------------------- | --- |
| 尺寸    | ≤ 290×195×210mm（V1.4） | 低底盘 + 紧凑布局，机械臂展开受控                                | 设计中 |
| 重量    | ≤ 2.0kg               | 轻量化底盘 + 塑料结构件                                     | 设计中 |
| 供电    | 单供电模块，≤7.4V           | 18650×2 串联 + 单一输出接口                               | 已实现 |
| 结构强度  | 180mm 自由下落无零件掉出       | 螺丝紧固为主，减少热熔胶                                      | 已测试 |
| 成本    | 新生组建议 ≤ 400 元         | 实际总支出约 **570 元**（含自费视觉模块约 50 元、为两台车备料），略超建议值，如实记录 | 超额  |
| 无线继电器 | 必须适配官方断电遥控            | 已纳入采购                                             | 待验收 |

> **为什么提前自检**：手册明确"不满足技术规范无法通过赛前检录"。我们把规范转化为可检查的清单，每次结构修改后对照核查。**尤其是尺寸规范从 260 放宽到 290 这件事，让我们意识到必须紧盯手册版本，否则一切设计都可能建立在过时数据上。**

## 五、总体问题与反思

| 时间    | 问题        | 影响           | 改进                |
| ----- | --------- | ------------ | ----------------- |
| 9/24  | 螺母漏发      | 轮胎无法拧紧、四轮不等高 | 增加到货清点环节          |
| 9/27  | 手册尺寸变更未同步 | 分工文档用的是旧尺寸   | 建立"以手册最新版为准"的核对习惯 |
| 9/27  | 工具寄错地址    | 装配延误         | 采购信息二次确认          |
| 10/8  | 万用表读数异常   | 一度误判电路故障     | 先排除工具干扰再判断电路      |
| 10月   | 舵机连续损坏    | 机构调试中断       | 关键关节改金属齿、加限位      |
| 10/16 | 视觉颜色误判    | 白色被识别为黄色     | 调阈值、要求方块更白        |

> **反思**：这次备赛最深的体会是——**"能跑起来"和"能稳定完成任务"之间有很大的距离**。螺母漏发、表具异常、舵机损坏这些"小问题"，恰恰是决定成败的关键。
